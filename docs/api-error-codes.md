# Event Service API Error Codes

這份表格整理 Event Service 對外可展示的主要錯誤結果。FastAPI 的請求驗證錯誤使用 `422`，不是 `400`。

| HTTP 狀態碼 | 情境 | 代表意義 |
|---|---|---|
| `200` | 查詢、新增、更新或刪除成功 | API 已完成要求 |
| `404` | 事件不存在、已過期，或已被刪除 | 找不到指定事件 |
| `403` | 非事件發布者嘗試更新或刪除 | 沒有操作權限 |
| `409` | 短時間內發布相同事件內容 | 重複內容被反垃圾機制擋下 |
| `422` | JSON 欄位格式、座標範圍、文字長度或內容審核不通過 | 請求資料不符合規則 |
| `429` | 發布過快、每分鐘次數過多或活躍事件過多 | 觸發發布頻率限制 |
| `503` | Redis、事件資料或必要儲存服務無法使用 | 暫時無法完成請求 |

## Demo 建議

1. 在 Swagger 的 `POST /events` 送出正常事件，展示 `200`。
2. 將 `latitude` 改成 `100`，展示 FastAPI 驗證回應 `422`。
3. 使用相同 `user_id` 與相同內容再次發布，展示重複內容的 `409`。
4. 使用不同 `user_id` 更新同一事件，展示權限錯誤 `403`。
5. 開啟 `/docs` 或 `/redoc`，展示 API schema 與請求欄位限制。
